After working as a DevOps Engineer for a while, I hadn't done much software development or touched Kotlin in years. To relearn the fundamentals, I started with the basics: Tutorials on [PluralSight](https://www.pluralsight.com/), various [YouTube videos](https://www.youtube.com/watch?v=e7tKQDJsTGs), and practicing with [Kotlin Koans](https://kotlinlang.org/docs/koans.html) examples. I decided I’d give vibe coding a try as well. 

From there, I created a local project to explore core concepts like OOP and inheritance, beginning with a classic Animal parent class and Dog, Cat, and Bird as children. The Cat class, naturally, overrode every method to do whatever it wanted regardless of input. 

As the project grew, I started using Claude AI to brainstorm new ways to apply concepts like interfaces, coroutines, and database connections. Using AI as a brainstorming partner turned out to be a genuinely fun way to learn, like pair-programming with someone who can recite the SOLID principles from memory but has never had to explain to a client why the button is red now. _Does anyone actually remember what L stands for anyway?_

By questioning its solutions, I was able to work through different scenarios and trade-offs, and pick up on concepts and edge cases I hadn't fully considered. That said, I could see how AI would confidently insert unclean code that technically met the requirements. I kept an eye on it through the GitHub Desktop GUI, reviewing what changed each time to understand where the AI was heading. 

Eventually, I decided to refactor the code into a VetClinic Software project, since there were more features and concepts I wanted to explore. The software uses Docker, a Postgres database, the pgAdmin interface, Gradle, and Ktor. I also use Postman to test API calls to the application.

### What I've learned so far
- Keep a running document to track concepts you want to explore
- Question the AI often
- Keep the AI from doing too much at once
- Push clean commits often to track progress clearly and quickly
- Maybe say please often in your prompts, just in case AI does become sentient

**In terms of vibe coding**, this project came together far faster than manually writing general boilerplate would have allowed. That speed gave me room to explore concepts like the repository pattern and security considerations instead. I especially enjoyed asking Claude to review my code for areas to refactor. It cut out the manual-code-monkey work and let me focus on the system as a whole.
